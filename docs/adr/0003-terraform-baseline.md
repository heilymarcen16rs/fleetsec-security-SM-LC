# ADR-0003 — Terraform security baseline & documented Checkov exceptions

- **Status:** Accepted · **Date:** 2026-08-23 · **Deciders:** Security Engineering / Cloud Platform

## Context
Entregable 03 asks for a `modules/security-baseline` module modelling a secure AWS
foundation, with `terraform validate` clean and a Checkov scan. Some requested
settings are actually **traps** (see ADR-0005) and some Checkov checks are out of
scope for a networking/data baseline (e.g. the ALB/ECS resources live in the app stack).

## Decision
Author a self-contained module (VPC 3-tier, KMS CMKs, S3 + Object Lock, RDS Multi-AZ,
Secrets Manager, CloudTrail, Config, GuardDuty, Security Hub, WAFv2) whose SGs are
consumed by the app stack via outputs. Drive Checkov to **0 failed** by fixing every
cheap real gap (default-SG lockdown, access logging, RDS IAM auth/PI/enhanced
monitoring, lifecycle, CloudTrail SNS, WAF logging) and adding **12 inline documented
skips** (`checkov:skip=ID:reason`) for intentional/out-of-scope items (e.g. ALB port
80 redirect per requirement, cross-region replication accepted risk, KMS root key
policy). Add a custom guardrail (CKV2_FLEETSEC_1 YAML + unit-tested Python).

## Consequences
- (+) `checkov` result is audit-grade: 251 passed / 0 failed / 12 documented skips.
- (+) The admin-port trap is enforced by built-ins (CKV_AWS_24/25) that PASS our SGs and FAIL a bad SG.
- (−) Full `terraform validate`/`plan` requires the candidate to run it (no cloud creds here); HCL syntax validated offline for all 12 files.
- (−) draw.io artifact is generated by the candidate from the provided Mermaid (delegated, with steps).
